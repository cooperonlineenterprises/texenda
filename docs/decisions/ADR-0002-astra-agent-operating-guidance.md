# ADR-0002: Astra agent operating guidance

Status: AUTHORITATIVE DECISION — owner accepted the repository-local operating
guidance through the 2026-09-13 audit instruction. The instruction-system
candidate `e3def2617753dd178e7d3eebae2e548b3e2df39b` was independently approved
and integrated; its review evidence was recorded at
`0a72aba450c76e318b02f22c49133b406da7d4ef`. Acceptance of this local policy
does not amend product authority or
[ADR-0001](ADR-0001-quality-first-model-routing.md).

The [source audit](../audits/2026-09-13-gpt-6-astra-agent-system-audit.md) found
that local permission and required completion were implicit in several entry
points, subscription interruptions had no concise resumption prompt, and the
qualification records conflated a desktop route with a separately installed CLI
version. The current coordinator already denies unqualified profiles, silent
fallback and unsupported downshifts; it does not dispatch or meter the runtime.

Use a concise root instruction file and the scoped
[operating guide](../agents/operating-guide.md). Route new assignments, independent
reviews and resumptions through the local prompts under
[tooling/coordination/templates](../../tooling/coordination/templates/ASSIGNMENT.md).
They retain the sealed assignment contract fields and add exact effort/runtime,
completion boundaries, usage observations and remaining bounds. The sealed
generic prompt remains preserved; it is no longer the active local entry point.
Generated context manifests are supplemented with the relevant local guidance
and selected template hashes before dispatch. No workflow requires reading all
specialist templates or unchanged archive material before each edit.

Ordinary authorized local work continues through required verification and
repair to a reviewable candidate. Clarification is for a material outcome,
governing conflict or authority gap. Complete independent local preparation
before asking for an external decision. These rules explain the existing owner
handoff; they cannot authorize an external effect or remove an independent
review or activation gate.

Usage pressure causes an interruption, not a lower quality route. Retain max
defaults, exact qualified profiles, WP floors, review depth and required checks.
Save a checkpoint, prove prior runtime stop, recover the lease/fence when needed,
and resume within the remaining authorized allocation. Subscription windows,
tokens, elapsed execution and retries require runtime observation/accounting;
the local ledger is not a meter. Repeated lease extensions do not enlarge owner
authority. Reset redemption, purchases and API spending need explicit authority.
No generic provider recommendation to start at lower effort changes ADR-0001.

The local `.codex/config.toml` keeps max effort, on-request approvals,
workspace-write sandboxing and network disabled by default, with no model
selection or copied profile roster. These are new-session project defaults;
verify actual runtime loading and effective permissions. They do not qualify
direct Astra CLI use. The [versioned correction plan](../qualification/runtime-surface-correction-plan-2026-09-13.md)
records the installed desktop/CLI distinction and the steps for a separately
attested replacement roster. Historical probes, timestamps, hashes and receipts
are never edited or backfilled from today's observations.

Optional visualizations are derived explanations of named source revisions,
with an accessible text equivalent. They preserve every relevant semantic
boundary and carry no authority. Source changes invalidate them until regenerated
and rechecked. No diagram, 3D pipeline or rendering dependency is introduced.

Deterministic authorization, untrusted-content handling, sandbox/approval
controls, independent review, immutable evidence and stop/recovery remain
necessary despite model safety improvements. Tests protect instruction routing,
template contracts, evidence/config integrity and interruption/recovery
behavior. They do not prove that an agent follows prose in every situation or
that provider identity/entitlement is independently known.

No executable lifecycle, schema, routing-policy digest, active roster, receipt,
WP, invariant, product contract, data migration or external gate changes here.
The sealed package remains byte-for-byte unchanged. Revisit these local defaults
only for an observed workflow conflict or changed runtime/source guidance;
material authority changes still need the established amendment process.
